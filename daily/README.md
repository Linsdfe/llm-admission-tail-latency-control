# 每日工作记录与成果（daily/）

目的：按日期留档**每天做了什么、产出什么、得出什么数据、遇到什么问题**。这是《开发流程计划》"每周记录投入、产出与阻塞"的底稿，也是阶段汇报、论文过程材料和日后复现的单一入口。

## 结构约定

```
daily/
├── README.md            ← 本文件：索引与写作约定
├── TEMPLATE.md          ← 新建某天记录时复制它
└── 20261019/            ← 日期目录（YYYYMMDD）
    ├── README.md        ← 当天工作记录（人工写）
    └── 产出清单.md      ← 当天产出文件清单（eod.sh 自动生成，勿手改）
```

规则：

1. **目录名用数字日期** `YYYYMMDD`（如 `20261019`）：排序自然、跨系统/脚本安全。
2. **每天一个 `README.md`**，按 `TEMPLATE.md` 写七块：任务、产出、关键数据、问题与处置、决策、下一步、收尾检查。
3. **日期目录只放"记录与清单"，不放文件副本**：正文写路径链接即可。正式文档在 `docs/`，证据在 `results/raw/`，工具在 `scripts/`（按功能分：`replay/` 测量、`ops/` 运维、`analysis/` 分析）。这样既有"按日期包裹"的入口，又不会产生第二份副本。
4. **一天一个目录**，没有工作的日子可以不建；有工作但中断的，记录墙钟跨度并注明"有效投入待核实"。
5. 编号习惯：任务 `T1…Tn`、产出 `O1…On`、问题 `B1…Bn`。
6. `产出清单.md` 由 `scripts/ops/eod.sh` 生成（按当天修改时间扫描全仓库），**不要手工编辑**。

## 每日收尾（下班前必做）

可调用 `$llm-project-daily`（[项目专用技能](../skills/llm-project-daily/SKILL.md)），或直接说“整理今天工作、按日期打包成果并更新 README 进度图”。技能维护当天记录、实验结果索引、进度与图示，并在 `results/archives/YYYYMMDD/` 生成带 SHA256 的每日成果 ZIP；`daily/YYYYMMDD/每日归档.json` 为最新归档回执。原始运行保留在 `results/raw/`，不把日志重复散放进每日记录目录。技能不自动运行新实验、提交或推送。

```bash
# 一条命令：清理临时文件/空目录 → 生成当天产出清单 → 同步 WSL → 一致性检查 → 打印待办
bash scripts/ops/eod.sh            # 默认今天
bash scripts/ops/eod.sh 20261020   # 补做某天
```

跑完后人工补三件事（脚本会打印提醒）：

1. 填 `daily/<日期>/README.md`（人时、问题、下一步）；
2. 在下面的索引表追加一行；
3. Windows 侧 `git add -A && git commit`。
