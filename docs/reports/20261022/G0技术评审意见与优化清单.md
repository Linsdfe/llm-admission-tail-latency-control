## 1. 优先补：主场景为什么值得优化，仍未闭合

**事实：** 强负载交互 P95 约 111–124 秒，额外排空约 118–131 秒，实际总输出约为独占的 10.50 倍。低强度三对 P95 仅增加 14.478–23.176 ms，均未达到本批预设的 100 ms 探索幅度。两个端点没有自动确定一个代表性正常主场景。

**影响：** 如果只是把负载调到等待很大，再展示优化，会主要说明过载下的取舍；若只在几十毫秒基线上报告百分比改善，也可能实际只省几毫秒。比如假设基线 40 ms，15% 只有 6 ms；这是算术示例，不是已测到的 B1 或 M 效果。

**优化：** 先写一页场景卡：谁在用、交互与后台分别干什么、到达与长度依据、可接受等待、最小有用绝对改善、愿意付出多少后台/吞吐代价、为什么属于拟服务范围。没有真实业务来源时，明确称合成工程假设。再据信息缺口决定是否需要新探针，不能反复加压直到出现理想差异。

**算够的标准：** G0 能解释“为什么值得做、研究什么范围”；具体 SLO、负载档位和最小改善量在 G1 冻结。原强/低负载继续保留为各自边界证据，不自动升级成正式主场景。

来源：开发计划 §3.1—3.2；开题 §6.3—6.4；两批实验报告。

## 3. 优先补：人时和范围仍是初估，不能认定已证明做得完

**事实：** 计划总计 250 人时、P0 30 人时；10-19/20/21 的有效人工投入都待本人核实。正式主场景以 10 配置×5 次起算约 50 轮，加两个次级场景最多约 100 轮基础运行，另有开发搜索、观测、故障、复验、稳定性、统计和论文工作。

**影响：** 真正容易超支的是实现、错误核查和分析人工，不只是一次模型运行多长。编译 12.8 分钟、批次 16.79 分钟都不能直接当作学生有效人时。

**优化：** 建两张表：本人有效投入/可用剩余人工；设备可用窗口/每轮完整周转时间/额外检查。G0 先提供可信区间和能承担的最小范围，G1 再固定完整矩阵。默认只承诺一个主场景，次级场景按明确问题逐个决定，R08、附加设备和模型继续排除。等价配置可以明示映射后共用运行，不能把独立比较伪装成重复结果。

**算够的标准：** 有本人确认的人工余额、设备日历、主要风险与减项顺序。超预算先删扩展和次级场景；保留 B3、简单规则、NN、必要消融和必要重复。

## 4. 后续最高技术风险：两个 slot 下，在线余量是否真的有用

**事实：** 当前两个执行位置，非主动抢占；硬预留按实际输入加最大输出，预测不减少硬预留。低强度输入记录对应的原始硬额度，交互约 107–111 token，后台约 446–447 token，尚未做分配粒度取整。两个后台合计约 894 token；C_safe 与执行细节尚未冻结，不能据此认定容量守卫永不触发，但需要警惕执行位置先成为瓶颈。

**影响：** 新交互到来时，已运行后台不会自动让位。软规则可能只是把第二个位置留空，或者很少作出与固定余量不同的决定；简单交互优先可能已得到主要收益。这是计划已识别但尚未验证的风险，不是已证实算法无效。

**优化：** G0 给一页机制解释即可。G2 列出同一状态下 M、B3 和简单规则分别放谁、为什么不同、交互何时到来、节省什么、牺牲多少空闲或后台时间。G3 先做最小可关闭原型，再决定是否投入完整 P4。

**算够的标准：** 日志以“硬约束允许决策点”为分母，记录分歧数量、对象、原因和伴随代价，确认存在可解释的作用路径；不设置无依据的触发比例门槛。没有空间时保留数据、收窄为适用边界研究，不必继续增加复杂组件。

来源：开题第 106–114 行；开发计划 §3.3、§4.1。

## 5. 后续核心证据风险：当前长度太好区分，未必能检验校准价值

本次从低强度 1230 行逐请求表重新提取：

| 类别 | 实际输入长度 | 实际输出长度 | 输出上限结束 |
|---|---:|---:|---|
| 交互 | 43–47 token | 11–33 token | 六轮交互均未触顶 |
| L 后台 | 62–63 token | 279–384 token | 三轮各 9/10，均为 90% |

强负载第 1 轮 E1 的后台另有 93/100 达到输出上限；此处只报告该轮核对范围。当前合成数据的两类输出区间完全分离，低强度后台还非常接近固定上限。

**影响：** 按类别给一个固定估计可能已相当有效；在线校准是否额外提供信息，尚无残差与真实决策证据。触顶请求的实际执行量已知，但自然结束时本来还会生成多长未知，两种目标不能混用。

**优化：** 开发集按桶输出：样本数、实际输出分布、正向残差、触顶比例、反馈滞后、冷启动回退；明确预测的是“给定输出上限下的实际执行长度”。如果以后同类请求的 max_tokens 不同，明确估计器如何使用或处理这个信息。M/B3 使用同预测器、相同可用信息和事先规定的调参预算。

**算够的标准：** G1 明确预测目标与信息；G2/G3 检查余量差异是否改变实际决定。可有一个预先说明理由的分布变化边界，不能故意只制造固定余量会失败的主负载。固定余量足够好，也是应保留的结果。

来源：低强度 `request-metrics.csv`；强负载 `r1-E1/replay/requests/`；回放生成器第 63–75 行；开题第 108 行。

## 6. 新定位的集成风险：延后以后，谁负责再次叫它进来

**源码事实：** 原生 `server_queue::defer` 把任务放到 deferred 队列；`process_new_tasks` 只消费主队列；slot 释放回调调用 `pop_deferred_task`，把等待者搬回主队列。事件循环的定时唤醒不自动重判 deferred。

**影响：** 如果未来照搬这条路径实现软延后，可能出现“还有一个位置空着，运行请求的剩余工作已经下降到可放行，但等待者仍拖到它完全结束”；老化或排队期限到时也未必自动触发候选检查。这是未来集成风险，当前自研策略尚未实现，不能称现有功能 bug。

**优化：** G2 固定统一重判事件：请求到达、decode 后软量更新、完成/取消/失败、老化到时、排队期限到时。它们进入同一候选检查，避免各处分散扣账，也避免忙循环。

**算够的标准：** G3 小轨迹验证：一运行一空闲，候选先被软条件挡住，条件满足后能在运行者结束前放行；没有新到达时老化和期限仍生效；没有重复预留。

源码定位：`third_party/llama.cpp/tools/server/server-queue.cpp:76`、`:90`、`:138`、`:353`；`server-context.cpp:1444`、`:3281`。已只读核对这些片段。

## 7. 指标需要补一份统一规格，防止改善只是换了计时位置

**现状：** P0 无外部闸门，计时边界和分母清楚。未来正式协议还有两个具体待落地问题。

1. 如使用外部闸门或客户端限流，实际发送后的 TTFT 不包含发送前等待。内部 C++ 接收后再等待则通常已经包含在客户端 TTFT。两种方式必须区分，不能把等待搬到计时开始之前。
2. P0 采用“完成请求最终总输出 / 含排空时长”；开题第 178 行拟采用“固定窗口内输出 token / 窗口时长”。两个指标都可以报告，但不是同一个量。只有最终 predicted_n 加 SSE 字符块时间，不能直接得到精确的窗口内 token 计数。

**优化：** 明确记录计划到达、释放、实际发送、内部接收/准入、首内容、终态。涉及闸门时，联合报告计划到达至首内容的总等待、闸门等待、发送后 TTFT；正常客户端迟发也单列。固定窗口输出计数需可靠服务端计数或已验证的 token 时间映射，不能按块数或字符数冒充。全程速率继续保留并明确名称。

**算够的标准：** G1 形成指标定义表，G3 用手算小轨迹对账。人为加入 1 秒闸门等待后，总等待应能体现这一秒；窗口边界内外的输出不能重复或漏计。本次没有发现 P0 因这两点作假，问题在未来规格需要落实。

## 8. 正式负载应避免只验证固定模板、固定碰撞时刻

**事实：** 交互固定 0.5 秒一条，后台固定在相对交互偏移 0.25 秒的位置；三对复用同一轨迹。生成器只有八个主题、两种主要提示模板。E0 每轮交互输入中，缓存 token 比例约为 `5775/(3016+5775)=65.7%`；这是 token 比例，不是请求缓存命中率。

**影响：** 固定相位可能反复避开或碰上相同执行阶段；大量共享前缀和很短输入也限制对长输入、随机或突发业务的解释。实际是否避开某一阶段，仍需观测，不能从相位独自断言。

**优化：** G1 写清缓存和到达政策；按提示模板或来源划分校准、开发与最终测试，不只改编号或种子。开发阶段用一个预定的相位/抖动敏感性小子集检查结论是否依赖固定碰撞。无需把所有相位、长度、缓存全部交叉成大矩阵；目标业务本来高度重复时可保留缓存并收窄结论。

**算够的标准：** 能说明测试集为何有独立内容，结论适用于哪种缓存/到达分布；若结果只在固定模板成立，就明确限定适用范围。

来源：`70_run_prestudy.py:63` 起；两批协议；实验工作量表。

## 9. 尾部精度与联合成功规则，需要从原则变成可执行判断

**事实：** 每轮 200 条交互，P95 靠近尾端约十条的位置；低强度后台每轮只有十条。C 三轮 P95 从 25.766 到 40.330 ms，范围约 14.564 ms。这个范围不是置信区间，也不能与配对差机械比较后宣布无效。每批只有三个配对效应重复单位；正式五次重复也只是预算起点。

**影响：** 很小的点估计改善可能不稳定；稀疏后台难以精确判断 P95 代价；100 秒窗口也未必足够观察在线校准的反馈循环或较慢的分布变化。

**优化：** G1 冻结主效应、最小有用绝对差、完整终态分母、运行层级区间与重复/时长调整规则；G3/G4 只用开发数据调整。稀疏后台需要更多观察时，优先考虑有依据的更长窗口，不能为了凑数提高到达率改变问题。P95 不可估或区间太宽时，报告证据不足；P99 仍只在充分时补充。

**算够的标准：** 交互收益、吞吐、后台完成与终态代价均有对应估计和不确定性，才能按事先规则判断联合目标。保留逐对结果，不能逐请求独立 bootstrap 伪造大量独立样本，也不把“没检出差异”写成等效。

来源：开题 §6.3—6.5；开发计划 §5；低强度报告。
