# P1筛选任务四条件诊断与负载收敛

这轮32次诊断已经完成，结论是：**单纯关闭输出约束，或直接给出当前状态，都没有把这版任务变成可用负载。工作质量维持88分，G1仍待审。**旧v14的2/48不改，不把这次已见资料诊断当作新过关成绩。

## 1. 这次怎么分开检查

固定8组已见资料，交互/后台各4组，分别覆盖无结果、1条、部分、全部符合。每组都跑四种条件，顺序作了平衡；模型、温度、缓存与输出上限均相同。32次请求对应16种提示、8组事实，不能当作32份新资料。

“当前状态”版本由程序从原文取出较晚的状态短语，保留原短语，不读取标准答案。它同时减少输入长度、去掉历史并改变说明语句，不能把它的效果单独解释成模型的时间比较能力。

## 2. 四种条件的全部成绩

|资料形式|格式约束|严格整题正确|只去首尾空白后正确|格式有效|达到输出上限|
|---|---|---:|---:|---:|---:|
|原两条时间记录|开（TG）|0/8|0/8|8/8|0/8|
|原两条时间记录|关（TU）|0/8|0/8|5/8|0/8|

|直接给当前状态|关（SU）|1/8|1/8|4/8|0/8|

后台每种条件都是0/4；“当前状态”两种条件各答对1道交互题，而且是同一组资料。移除时间记录在这8组中只改善1组，关闭约束在两种资料形式下都没有增加严格正确数，不能宣称已经定位并修复根因。

原时间＋约束的8份输出全部逐字复现旧结果，说明这次没有换掉旧失败。所有32条正常结束、无缓存、无输出上限截断，原生34次启动/34次释放闭合（含2预热）；独立证据审计514项通过。批次单调耗时40.795秒，外层worker41.363秒。程序运行时间不填作人工投入。

## 3. 格式正确和选对内容要分开

格式约束保证编号升序，但没有保证选对编号。例如R4121、R4123都应选中：

- 当前状态＋无约束输出“R4123、R4121”，编号选对但顺序错，严格评分仍错。
- 当前状态＋有约束只输出“R4123”，格式正确，却漏掉R4121。

无约束臂共7次编号乱序，未发现额外解释文字。采后另数“忽略顺序的集合匹配”，四臂为0/8、0/8、1/8、2/8；这只是说明错法的附加计数，不替换表中的采前指标。不能因为格式更整齐，就说模型更懂资料；也不能因一例集合改善，就说关闭约束解决了问题。

2组应无结果、2组应全部选中的资料，在四种条件下都错。即使不需要再比较时间，当前配置仍无法可靠完成条件筛选，不能继续把这些错答的长短变化当成调度算法的价值证据。

## 4. 有没有明显的调用问题

对本批16种提示做了采后只读检查：用服务记录的模板离线渲染，全部与实际提示逐字相同；输入中的ChatML标记也全部符合预期。没有为此重新启动模型或新增推理。

这排除了所检查范围内明显的模板拼接与特殊标记问题，不能排除所有量化、运行时或模型能力问题。此次证据支持的说法是“当前整套本地配置在这些任务上表现不可靠”，而不是“已经证明某个单独因素是唯一原因”。

## 5. 接下来收敛什么

原课题继续研究推理准入与尾延迟控制，不继续追着这版筛选提示改写。筛选支线保留为失败与适用边界；下一份候选回到明确目标编号的提取、整理，先用新资料验证任务质量和实际工作量，再决定调度对照。

新候选若按请求指定目标条数产生长度差异，条数就是公开信息，简单强对照也必须使用。不能拿公开规则已能算准的长度变化证明在线校准必要；M没有增益的交付路线保留。

任务种类、桶划分、至少32条暖启动、校准量及正式矩阵必须一起重列，不能偷偷把两任务当成原六桶配置继续跑。当前没有改旧正式候选参数，没有启动调度比较、最终测试或新一轮提示尝试。具体事项见[负载收敛候选卡](../../p1/workload-scope-convergence-after-v15.md)。
