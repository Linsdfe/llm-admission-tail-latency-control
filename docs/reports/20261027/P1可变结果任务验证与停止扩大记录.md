# P1可变结果任务验证与停止扩大记录

实验于2026-10-26运行，2026-10-27完成报告与跨日收尾。本轮新任务没有通过：**48道题只完整答对2道，不能进入调度对照。阶段工作质量维持88分，G1仍待审。**

## 1. 这次实际验证什么

旧任务预先规定输出几行，长度太固定。这次改为读工单资料：每条工单有两条带时间的状态，只根据时间较晚的一条，筛出仍不可用的编号；没有符合条件的就输出“无”。正确答案条数随资料内容变化。

两组新开发资料，每组12交互＋12后台，共48份唯一资料。交互每题4条工单，后台8条，事先安排了无结果、少量结果、全部符合等情况。这是覆盖测试，不代表线上业务分布。格式约束允许所有编号的全部升序子集及“无”，没有把正确子集或输出条数告诉模型。

使用原固定本地3B模型与引擎、自然结束、temperature0、无缓存。48测量＋2预热全部完成，原生50次启动和50次释放闭合，服务正常退出；外层程序耗时140.074秒。10月27日只做核对和收尾，没有新增GPU生成。最终资料未生成/访问，没有调用远程模型API。

## 2. 数据和验收结果

|项目|采前要求|实际结果|结论|
|---|---|---|---|
|完整答对|至少46/48|**2/48，约4.2%**|未通过|
|交互完整答对|至少23/24|2/24|未通过|
|后台完整答对|至少23/24|0/24|未通过|
|正确且非空的答案长度|每类至少3种实际token数|交互只有6、18；后台没有正确样本|未通过|
|执行、计数和来源|全部可核对、无上限截断、无缓存、原生释放闭合|48条全部正常结束，13690项主核对＋2638项来源核对通过|技术记录通过|

“技术核对通过”说明请求、输出与原始记录对应，不能把2/48答对改写成任务通过。

交互实际输入176—181 token、输出6—18 token；后台实际输入280—288、输出6—30。虽然输出长度有变化，大部分却是错选、漏选后的长度。不能拿这些变化证明复杂调度算法更有价值。

## 3. 具体错在哪里

|例子|资料与标准答案|模型实际输出|问题|
|---|---|---|---|
|第1题，交互|4条工单在09:40都已恢复，应输出“无”|R4101、R4102、R4103|把已恢复的工单也选进去|
|第5题，交互|4条全都仍不可用，应输出全部4个编号|只输出R4140、R4143|漏掉2条|
|第18题，后台|8条全都仍不可用，应输出全部8个编号|只输出R4270、R4274、R4276、R4277|漏掉4条|

48题中，29题有漏项、26题有多项，两个分组有重叠；合计漏63个编号、多选48个。10道“应当没有结果”的题全错，10道“应当全部选中”的题也全错。[48题全部标准答案与模型输出](../../experiments/20261026-p1-content-profile-v14/逐题结果.md)均保留，没有删差例。

这能确认整套“提示＋资料形式＋输出约束＋模型配置”不合格。还不能单独断言错因就是时间比较能力或输出约束；本轮没有分别改变这些因素做对照。助手逐条核对了48份输出与标准答案，并查看代表性输入，不代表学生或导师已经人工审核。

## 4. 简单规则给出的信息

采前另写了直接读取公开资料的规则程序：找到每条工单时间较晚的状态，再算应输出的编号和文本长度。它只读取实际提示，不读生成器的隐藏答案，在本有限模板中与独立事实48/48一致。规则本身就能完成这个任务，不能据此声称该任务需要LLM或复杂调度。

但模型答错后，实际输出可能与规则求出的正确答案长度不同。规则预测实际输出长度只精确命中4/48；在仅有的2道完整正确题上误差为0。交互全样本平均绝对误差7 token，后台约13.92 token。这不构成在线算法的机会证明，先要解决答题质量。

历史规划资料按evaluation-plan、trace、plan、warmup-plan四类完整查重，共核对2295个历史规划文件、1946种历史提示；本轮48份均未重复。这里只是两组开发小样本，不是48次独立系统性能重复。

## 5. 现在怎么处理

按采前约定，停止扩大这版任务的调度实验，不在本轮改提示、换模型或降低门槛补考。旧48次结果和原规则保留。固定五项评分仍为16/16/18/19/19＝88分；没有因为多跑一次或多做检查而加分，G1不自动通过。

下一项建议另立一次小规模故障定位对照：先按“无结果、1条、部分、全选”预选8组已见事实，再分别比较“原两时间记录/明确当前状态”和“有/无输出格式约束”，共32次。它只能定位输入理解与约束的影响，不是新独立验证，更不能替换本批2/48成绩；是否执行以新的采前协议为准。本次收尾未执行这32次。

原因查清、另用新资料通过任务质量门槛后，再决定采用什么负载和同信息强对照；不能继续在错误答案上扩大调度轮数。完整原始证据按跨日收尾归入10月27日日期包，保留原10月26日run_id，GitHub公开代码和派生报告。
