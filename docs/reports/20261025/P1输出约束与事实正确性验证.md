# P1输出约束与事实正确性验证

2026-10-25，Asia/Shanghai。当前P1，G1待审。

**输出约束解决了格式问题，但没有解决全部事实错误。同一批24道新题，无约束完整答对10道，加约束后答对15道；仍有9道实际抄错数或比较错。**

## 这次怎样验证

本轮没有只挑上次成功题。新生成24道开发题，提取、核对、整理各8道；每道用同一份资料、同一个提示、同一模型和同一输出预算各跑两次，一次不限制格式，一次限制格式。12对先不限制、12对反过来，避免全部第二次执行都落在一种模式。

限制格式是在引擎解码时要求模型只输出指定编号、指定行数、指定顺序。数字仍允许10—99全部90种，核对仍可选“一致”或“不一致”；约束没有提供正确数值或替模型比较。资料与正确答案由独立程序离线核对，正确答案未作为额外字段发给模型。

采前固定[协议](../../p1/output-constraints-pilot-protocol-v4.md)、[判分规则](../../p1/output-constraints-evaluation-rubric-v4.md)及代码SHA。18项新单元测试、36组独立核对反例和完整原生客户端门禁通过后，才启动GPU。首次模型外门禁因WSL路径别名准备失败，保留原记录，另建目录统一路径后通过；没有改模型、题目或评分标准。

实际10:41:27—10:46:01在WSL完成48条测量＋2条预热，采集耗时273.960秒。所有测量完成，2836项独立原始核对通过，最大迟发10.086ms，50次请求的100条启动/释放事件闭合，缓存输入0、服务退出0、来源/模型/运行库未变。

## 剩下的具体问题

| 例子 | 原资料和应答 | 加约束后的实际回答 | 说明 |
|---|---|---|---|
| `i004-g`核对 | R1在两份资料为54和55，应“不一致” | `R1|一致` | 格式完全正确，但比较错 |
| `b002-g`提取 | R6的原值是88 | `R6|31` | 仍把另一个数写给目标编号 |
| `b003-g`提取 | R1应47 | `R1|22` | 编号、行数对，值错 |
| `b009-g`整理 | R5应47、R3应97 | 写48、38 | 顺序对，两个值错 |

完整编号带前缀`v4-24001-`。更明确的现象是：**有约束模式的8道核对题，把28个核对字段全部写成“一致”**；原资料实际14项相同、14项不同。于是字段只对14/28，整题只对2/8。这说明本批不能靠“只能选两个标签”保证它真的比较了资料，也不能据一版指令就断定模型永远不会比较。

9道剩余失败由6道核对、2道提取、1道整理组成，共18个目标字段错误。限制格式后全部字段都能合法解析，因此本批这些剩余错误确实是数值或结论不符，不再只是缺编号或表头问题。[24对逐条表](../../experiments/20261025-1045-p1-output-constraints-v4/metrics.md)和[全部题目、48份回答及差异](../../experiments/20261025-1045-p1-output-constraints-v4/fulltexts.json)均保留，助手全文核读另列，不冒充学生或导师盲评。

## 下一步做什么

本轮未达到采前“有约束24/24完整正确”的继续条件，G1保持待审，不扩大调度实验。

下一项保留已经验证能工作的格式约束，另登记一次更明确任务指令的对照：把核对要求写清为“同编号在A、B中的数值相等写一致，否则写不一致”，同时分别核查取数与比较，不向语法注入正确值，不看结果后筛成功题。如果仍失败，再据证据调整模型适配方案，避免无限修改表面格式。

这只是固定字段资料任务的底线检查，普通程序也能完成，不能包装成LLM应用创新。本轮单次串行合成开发数据不估计总体业务可靠率，不说明并发干扰或复杂调度是否值得。原在线余量M与同信息固定余量B3主比较保留，尚未实现；新任务未重新校准，旧分界64和旧性能不直接沿用。
