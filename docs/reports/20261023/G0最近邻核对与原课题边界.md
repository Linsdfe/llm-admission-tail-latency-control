# G0 最近邻核对与原课题边界

核验日期：2026-10-23（北京时间）。本文为新增阶段审查材料，不改写开题或既有实验报告。本次联网核对六篇原文的方法段及正式出处；没有复现作者代码，也不是穷尽检索。出处、版本和核验范围见[来源记录](../../../results/raw/maintenance/20261023-g0-nearest-neighbor-check/source-note.json)。

**结论：混合服务、短优先与长任务保护、预测误差校准均已有直接研究。原题仍可保留为一项具体、可失败的系统实验：在线余量 M 相对同信息固定余量 B3，是否产生值得其代价的额外服务收益。当前不能认定方法创新或代填导师 G0 批准。**

## 1. MAPS：与在线余量最直接重合

[正式出处：ICML 2026](https://proceedings.mlr.press/v306/zhang26s.html)；[原文 v1，§3.1—3.3、式(2)—(6)](https://arxiv.org/html/2609.15359v1)。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 设备预测长度、云端校准上界，再分配解码实例及排序。 |
| 状态—触发—动作 | 保存最近已完成请求的正向残差；新请求到达时，给点估计加残差分位数，结合空闲/预留KV块和队长路由；完成后更新窗口。 |
| 保证与限制 | 原文明列交换性假设下的边际覆盖；非平稳滑窗效果属经验结果。统计长度上界不是绝对容量或逐请求延迟保证。 |
| 对我们意味着什么 | M的核心余量形式已有直接先例，必须与B3比较实际准入收益。 |
| 不能认领的创新／适配限制 | 不能认领在线残差校准本身。其设备—云及多解码器架构不同，完整性能不能移植到单实例。 |

## 2. QBA：与短长请求保护的权衡直接重合

[原文 v1，§III-A4—6、IV-D—E](https://arxiv.org/html/2610.17795v1)；[arXiv 状态页](https://arxiv.org/abs/2610.17795)。2026-10-13公开；作者注明IPCCC 2026已接收，11月会议尚未举行，本次按公开预印本引用。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 在预测短优先与长请求老化之间用配额控制晋升。 |
| 状态—触发—动作 | 观察预测类别、等待历史、短准入计数和晋升欠账；老化且配额到位时优先准入最老长请求；实际准入后清账。 |
| 保证与限制 | 欠账避免晋升被新短请求反复冲掉；不等于任意过载下的完成时限。主要证据是服务感知仿真；作者明确部分条件FCFS尾延迟更低。 |
| 对我们意味着什么 | 可作为NN候选，检查均值与类别尾部的代价。 |
| 不能认领的创新／适配限制 | 配额、老化及其折中不是新概念。需明确短准入计数、分块延续和KV可行性语义；业务后台不自动等于预测长类。 |

## 3. TIE：预测不确定性与动态风险权重已有研究

[正式出处：ICML 2026](https://proceedings.mlr.press/v306/zheng26ae.html)；[原文 v1，§3—5、附录E](https://arxiv.org/html/2604.00499v1)。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 预测输出长度分布，用期望加尾部风险替代单点长度排序。 |
| 状态—触发—动作 | 根据预测分布、输出上限、队长和等待时间更新分数；高压力提高风险权重，久等降低分数，空位时选最小分数。 |
| 保证与限制 | 等待衰减提供防饥饿机制；不是硬容量或端到端时限证明。训练需要同提示多次生成，作者列为限制。 |
| 对我们意味着什么 | 不能只以预测误差下降证明调度有效，须评价排序与服务结果。 |
| 不能认领的创新／适配限制 | 尾部风险加权、随压力调权已有先例。其分布预测器不等于本项目分桶估计器；换掉信息后只能称规则适配。 |

## 4. Beyond Prediction／UniBoost：自适应尾延迟调度已有研究

[正式出处：ICML 2026](https://proceedings.mlr.press/v306/li26n.html)；[原文 v1，§3.2—3.4、§4](https://arxiv.org/html/2606.18431v1)。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 不逐条预测总长度，用平滑优先级、KV感知抢占防抖和在线参数调整控制尾部。 |
| 状态—触发—动作 | 观察到达时间、已执行量和历史尾延迟；更新优先级及参数，达到量级阈值后再考虑抢占，避免频繁缓存搬移。 |
| 保证与限制 | 给出重评机会数量约束等机制分析；不能外推为任意GPU批处理下的普遍最优或SLO保证。 |
| 对我们意味着什么 | “不同负载需要不同程度调度”和“自适应控制尾部”均非空白。 |
| 不能认领的创新／适配限制 | 不能泛称首次自适应调度。其跨阶段抢占与KV控制能力超出当前非抢占原型，需单列实现差异。 |

## 5. ConServe：同机在线／离线协同服务已有直接系统

[正式出处：ICML 2026](https://proceedings.mlr.press/v306/qiao26i.html)；[核验的方法版本：arXiv v2，§4.1—4.4](https://arxiv.org/html/2410.01228v2)。方法核验使用2025-09-03预印本，不声称已逐字核对会议PDF。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 在线请求优先，用离线任务利用空余GPU，结合细粒度抢占和增量KV管理。 |
| 状态—触发—动作 | 每轮根据计算token、既有上下文及TBT目标算预算，填入离线token；在线突发时层间抢占，并按需释放/恢复离线KV。 |
| 保证与限制 | 延迟预算依赖离线标定模型与执行能力，不能据此推出未知负载绝不违约。 |
| 对我们意味着什么 | “聊天少等且利用后台吞吐”已有直接研究，必须明确本项目的受限动作集合。 |
| 不能认领的创新／适配限制 | 在线优先、预算填充和混合服务不是新主张；层间抢占、缓存传输需深度执行器支持，不能拿请求级上限冒充复现。 |

## 6. HyGen：预算、后台保护与较小单卡部署也已有先例

[正式原文：NeurIPS 2025 PDF，§4、附录A](https://proceedings.neurips.cc/paper_files/paper/2025/file/15e92839359df6d22e80042e572538d4-Paper-Conference.pdf)；[对应HTML v4，§4.1—4.3、§5.1](https://arxiv.org/html/2501.14808v4)。

| 审查项 | 核对结果 |
|---|---|
| 已经做什么 | 双队列混合服务，预测批次时间、标定SLO预算，兼顾后台前缀复用与防饥饿。 |
| 状态—触发—动作 | 每轮先处理在线，再按剩余延迟/内存预算加入后台；必要时抢占后台，后台次序兼顾前缀收益和最久等待。 |
| 保证与限制 | 预算由目标硬件和工作负载标定；防饥饿机制不等于持续在线过载时后台仍有固定完成期限。 |
| 对我们意味着什么 | 必须比较预测控制相对固定限速等强基线，单纯混合服务意义不足。 |
| 不能认领的创新／适配限制 | 在线优先、预算和后台公平已有系统。原文还测了单张24GB A5000；更小显卡仅是适用条件，不能单独作创新。 |

## 保留原题后，实际要检验什么

原题及用户已选择保留的范围见[原课题执行卡](../../original-topic-next-step-v1.md)。下面均是**待验证假设**，不是本次文献调研证明的结果，也不将研究改成“发明通用最优调度”。

| 待验证命题 | 后续必须提供的证据 |
|---|---|
| 在固定容量、有限槽位、非抢占执行下，M有实际决策空间 | G2给出同一状态下M/B3不同决定；G3用最小原型记录硬约束允许机会、软规则介入、空闲与后台代价。手算例子不算性能验证。 |
| 在线更新比固定余量有额外收益 | M/B3共用点估计器、分桶、候选顺序、后台保护、硬守卫和执行设置；B3用开发集选择并冻结，M只读当时已完成反馈；分别记录反馈滞后与完成样本选择。 |
| 增量足以抵偿复杂度 | 预先确定有实际意义的绝对/相对收益及后台、输出速率、终态和计算开销容限；保留简单规则、至少一种NN及必要消融；最终测试独立锁定。未检出差异不直接证明等效。 |
| 校准可用，但不冒充安全证明 | 预测目标为输出上限内的实际执行长度；触顶和失败分别记录。硬容量独立强制，经验残差覆盖不自动成为交换性下的conformal保证或逐请求保证。 |

G0可据此评审问题依据、与已有工作的重合、可实现范围和后续证伪路径；不要求此时先证明M获胜。若后续M/B3几乎不产生不同决定，或增量小于代价，应保留不利结果并收窄结论。当前仍需导师／项目正式范围认可；本记录不替代批准，也不证明尚无人完成相同情境研究。
