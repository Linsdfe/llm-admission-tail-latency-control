# P0 第七、八步执行协议

本协议随本次采集开始前固定的 `configs/prestudy-e0e1.json` 使用。配置副本及执行源码快照保存在对应批次的 `protocol.json`、`source/` 和 `code-sha256.json`；后续配置修改不能改变已采集批次。

## 第七步：终态与统一排空

`tests/integration/verify_open_loop.py` 通过可控本地 HTTP/SSE 服务核对完成、429/503 拒绝、400/断流/缺少 DONE/非法 JSON 失败、请求总超时、主动取消、统一截止未完成和未释放请求。每条计划请求具有唯一 ID、唯一终态、独立 JSON 与汇总记录；各类计数之和等于计划数。首内容排除心跳、元数据和空块，HTTP chunk 边界与 UTF-8 分段不改变 SSE 解析。

请求超时覆盖本次连接与流式接收全过程；统一截止为测量窗口结束再加排空期限。截止时取消本轮未结束任务并关闭连接，尚未释放的计划请求也记作未完成；不等待后台阻塞线程自行退出。客户端完成时间记录本地终态，不等同于引擎内部清理完成。

完成/取消竞争使用 20 条请求核对不会重复记录；每秒 20 条、200 请求的发送能力校准检验固定 50 ms 迟发门槛，明显高于预实验平均每秒 3 条负载。此前每秒 500 条的过载尝试迟发明显，保留失败证据；未放宽门槛，也未依据 E0/E1 结果调整规则。

真实 llama.cpp 另核对主动取消、总超时、统一截止与未释放，再在同一服务上执行两条恢复请求，保存前后 metrics 与服务端日志。处理和等待队列归零是本阶段的观测，不替代后续 KV 硬账本、序列回收和幂等释放工程验收。

## 第八步：三组配对预实验

| 项目 | 固定设置 |
|---|---|
| 运行 | 3 个重复，每重复 E0 和 E1，共 6 轮 |
| 请求 | E0 200 交互；E1 相同交互 + 100 后台 |
| 到达 | 交互 500 ms 间隔；后台从 250 ms 开始，每 1000 ms 一条 |
| 数据 | 合成中文 prompt，轨迹种子 20261020；三重复复用相同轨迹 |
| 输出 | 交互 max_tokens=64；后台 max_tokens=384；报告实际长度 |
| 模型/引擎 | 与环境记录中的固定版本及模型一致，每轮记录完整 SHA |
| 服务 | `-ngl 99 -c 4096 -np 2 -b 2048 -ub 512 --metrics` |
| 缓存/预热 | 每轮重启，默认前缀缓存，两条固定预热且不计样本；记录 cache_n/prompt_n |
| 顺序 | E0/E1、E1/E0、E0/E1 |
| 窗口 | 100 s 测量窗口，再最多 180 s 排空；单请求总超时 180 s |
| 时钟 | 同一客户端进程 `time.monotonic()`，偏移和差值以 ms 保存 |
| 迟发 | 每条实际发送−释放时刻 ≤50 ms；超限逐条保留并标记，不删除 |
| 分母 | 无外部闸门按窗口内实际发送计数；同时报告全部计划请求与终态 |
| 吞吐 | 窗口完成 req/s 单独报告；全程输出 token/s 使用包含排空的实际结束时长 |

输出上限不等于实际输出长度，业务类别不是长度标签；合成输入不代表生产分布。引擎默认前缀缓存会命中模板前缀，不能声称所有请求都是冷缓存。

本轮 `t_actual` 取 TCP 连接建立后、写入 HTTP 请求前的客户端单调时钟；连接建立和本地调度等待计入发送滞后，不计入从实际发送开始的 TTFT。两场景采用相同边界；不要直接把本轮数值与旧 urllib 冒烟的调用前边界作严格性能对照。保存的是同一回放进程内相对起点的时间，不用它与服务端或 GPU 的墙钟相减。

若迟发超限、终态不闭合、缺日志或版本不一致，则标记需要复核并保留原始运行。不要在结果出来后挑选完成请求来掩盖失败，也不要把成功请求 TTFT 当作全体服务质量。

每个重复单独计算交互 P50/P95 及 `Δ_r=P95(E1_r)−P95(E0_r)`，并列全部终态、实际 token 数、缓存量、后台从计划到达计算的完成时延、测量/排空和吞吐。三次重复只用于探索，不承担正式显著性判断。内部软预算与长度异质性的因果解释仍需后续对照。

## 运行和分析

在 WSL 使用 Windows 主仓库的脚本（日志直接保存主仓库 `results/raw/prestudy/`），避免依赖未同步的副本：

```bash
python3 "$HOME/proj-win/tests/integration/verify_open_loop.py" --out-dir <新建的第七步证据目录>
python3 "$HOME/proj-win/scripts/replay/70_run_prestudy.py" --step7-dir <已通过的第七步目录> --out-dir <新建的批次目录>
```

完成后运行 `scripts/analysis/80_analyze_prestudy.py --batch <批次目录> --output <新建分析目录>`。分析目录应保留版本，每次修改分析使用新目录，不覆盖已引用结果。日期归档同时包含第七步失败尝试、通过尝试和第八步完整批次。
