# 临时预测与余量空间检查

本检查只使用已完成的校准和开发数据，不生成最终测试、不模拟调度、不比较算法收益。每桶只有4条校准，以下临时中位数不作为冻结预测器。

|类别|输入桶|4条实际输出|临时预测|输出上限|还能增加多少余量|
|---|---:|---|---:|---:|---:|
|后台|0|[100, 384, 339, 264]|301.5|384|82.5|
|后台|1|[384, 384, 384, 384]|384.0|384|0.0|
|后台|2|[243, 384, 204, 384]|313.5|384|70.5|
|聊天|0|[12, 25, 11, 37]|18.5|64|45.5|
|聊天|1|[23, 64, 51, 60]|55.5|64|8.5|
|聊天|2|[64, 64, 64, 49]|64.0|64|0.0|

聊天的第2号桶、后台的第1号桶，临时预测已经等于输出上限。若继续按输出上限裁剪，加多少正余量也不会改变这两桶的输出长度上界；各开发轮约三分之一请求处于此情况。其他桶仍有余量空间，真实软决策还取决于负载、候选和保护规则，不能据此宣称M/B3整体没有区别。

QBA适配卡原拟用全部24条校准输出的85%分位作长短分界，本次得到384 token。临时预测都不超过该值，按草案规则，9轮全部预测为短请求，长请求提拔机制无法发挥作用。校准按类平衡采样，主场景类比例不同，分界的总体口径也需要说明。

G1前应重新审查校准规模、点估计和长短分界，记录退化与适配差异。可以在开发期比较有使用依据的长度阈值或与目标请求比例一致的分位方案，锁定后再测试，不能依据最终结果挑一个弱最近邻。当前不修改已采集数据或提示，也不认定原论文方法无效。
