# 架构阅读指南

本项目研究交互请求和后台任务共享一个 LLM 推理实例时，如何控制请求准入时机与候选顺序。计划以 C++ 接入 llama.cpp；模型计算与流式生成仍由引擎负责。两类请求是业务标签，不等于事后实际输出长度。

| ② 目标 | 准入、后台保护、执行与校准如何分工？ | [目标架构图](../images/system-architecture.svg) | [target.html](target.html) |

下载或克隆仓库后，直接用浏览器打开 [index.html](index.html)，可在三图之间切换并查看说明、缩放和导出。所有交互资源包含在 HTML 内，不需要安装依赖或启动推理服务；这些相邻 HTML 文件应保留在同一目录。GitHub 文件预览展示 HTML 源码，因此仓库首页嵌入静态 SVG。

## 现状与目标不要混读

当前已实现批次编排、开放到达客户端、原始记录、离线审计与本地归档，原始 llama.cpp 已可运行。C++ 核心目前是目录骨架，接入、软准入、在线校准、后台保护、硬容量记账与完整服务端事件插桩仍待实现。

目标设计依次覆盖：登记类别、ID、时限与输出上限；选择候选；检查硬约束与软工作量；准入并预留；引擎执行；停止、清理、安全回收；以有效完成样本更新后续软估计。当前客户端直接访问原始引擎。具体接口、优先级和参数仍需后续设计冻结。

## 术语速查

| 术语 | 在本项目中是什么意思 |
|---|---|
| 准入 | 决定请求何时获准进入执行；到达不代表立即执行 |
| 硬容量与硬预留 | 按实际输入长度加最大允许输出保守预留，并检查总容量、单序列和槽位；不能因预测乐观而缩减 |
| 软工作量预算 | 用未处理输入及预计剩余输出估计忙碌程度；超限可暂缓，是局部成本近似，不是时延保证 |
| 在线校准 | 使用当时已完成且有效样本的实际生成长度更新正向误差余量；不能使用未来信息 |
| 后台老化与保护 | 等待达到阈值后进入保护集合，在硬容量允许时获得接纳机会；不承诺任意过载下的有限等待 |
| slot | 引擎中承载一个执行序列的位置 |
| prefill / decode | 先处理输入提示词，再逐步生成输出 |
| TTFT | 从实际发送到收到首个非空生成内容的时间，排除心跳、元数据和空块 |
| P95 | 样本的第 95 百分位，用于描述较慢请求，不等于最大值 |
| 安全回收 | 执行停止、序列清理、槽位可复用后才一次性归还账本；逻辑释放不等于显存立即返还操作系统 |

**示意例子，非实验数据：**实际输入 100 token、允许最大输出 300 token，硬预留基础量是 400 token，还需按分配粒度取整。即使预测输出只有 50 token，也不能把硬预留缩成 150；该预测只参与软工作量判断。
