## 目前的具体方案

采用单卡、单模型、两执行位置的合成工程场景。主场景暂定100秒内200条聊天，后台30条、每10秒集中到达3条。平缓后台和稀疏后台作为边界。选择依据是P0已观察到聊天等待与后台完成之间的取舍，尚未验证在线余量是否占优。

暂用聊天P95不超过1秒、至少改善100毫秒且15%、后台P95增幅不超过20%、全程输出速率损失不超过5%作为工程目标草案。这里P95指约95%的请求不超过的时间；正式主指标从计划到达算到首段回答，实际发送后等待另报。

在线余量和固定余量共用估计器、候选顺序、后台保护、硬容量和执行设置。两者的关键差别是余量是否在线更新。对照仍保留原始引擎、公共硬守卫、简单优先、配额、长度排序、最近邻和必要消融。
