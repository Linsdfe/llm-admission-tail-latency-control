# P1可直接核对的资料任务：小批验证协议v3

2026-10-25，Asia/Shanghai；在本轮真实模型生成前登记并保存SHA。用户已明确要求先把任务限定为可直接核对的资料提取、核对和整理，再验证。原v1/v2任务、全部原始数据和既有评审决定保留；当前P1、G1待审，不改开题正文。

## 1. 本轮要验证什么

旧任务要求模型从少量合成数字做开放分析，出现无依据人员配置、趋势、记录编号和漏答。v3改为从已给资料复制指定事实、比较两个明确字段、按已给顺序输出记录；不要求推断原因、正常范围、资源配置或未来趋势。

这是一次业务任务变更，不是仅调整提示措辞。不能把v3与旧任务的正确率、时延或输出长度差异当作调度策略的效果，也不把任务设计称为新调度算法。原M/B3同信息增量主比较保留，尚未实现或验证。

## 2. 三种任务与答案边界

源资料使用唯一编号和明确的字段值。提示只包含任务要求、实际资料、目标编号和输出约定；正确输出参考保存在离线评价元数据，不作为额外答案字段或标准答案提示发给模型。资料本身当然含有待提取的事实，这属于任务输入。

| 任务 | 模型做什么 | 允许输出 |
|---|---|---|
| 提取extract | 查出指定编号的原字段值 | 每行`ID|值`，按目标编号列表顺序 |
| 核对check | 比较甲、乙两份资料中同编号的字段值是否相同 | 每行`ID|一致`或`ID|不一致`，按目标列表顺序 |
| 整理organize | 将目标编号的原字段值按明确指定顺序重排 | 每行`ID|值`，不自行排序或补信息 |

聊天类提取/核对各查1个目标，整理查2个目标；后台类每种任务均处理6个目标。不再要求“两句话”或开放六点分析。字段和编号按源值精确核对，没有资料依据的说明不能当作额外有效答案。

本轮源记录中目标全部存在且唯一；核对任务的两份源记录均完整。生成器缺失/重复目标或不合法事实是输入错误，采集停止并保留，不能当作模型答错。单元测试应拒绝这些无效输入。

## 4. 评价方法先固定

按[评价规则v3](verifiable-task-evaluation-rubric-v3.md)独立从源事实和目标编号重算答案，不导入生成器求正确结果，再与离线expected元数据交叉核对；两者不一致按测试工件错误停止，不能用一套可能同错的生成代码同时造题和判题。

主业务核对只规范化无意义空白：CRLF/CR换行、纯空白行、ASCII竖线两侧字段首尾空白。不得改编号大小写、字段值、核对标签、行顺序、重复/缺失/额外记录；不得删除非空表头、说明、代码围栏或把全角符号改成ASCII。原始字节完全一致可另报，不能因无业务意义的空白就把事实正确回答判错。

分别报告输出结构、ID、字段/一致标签、顺序、缺失/多余行和额外非空文本。保留原输出、期望、规范化结果和差异；EOS、合法长度、低重复不自动通过。补看全部24份原题和输出，检查机器核对是否对应实际任务要求；助手核读不冒称学生或导师人工审核。

采前进入条件为24/24均完成规范化后的字段事实、顺序和无额外非空输出，且全部技术完整性核对通过，才允许另登记新长度/校准及小规模负载开发检查。这个小样本条件不是总体正确率保证、G1批准或调度收益证据。

如有失败，按种类、输入档、具体错误逐条列出；不删样本、不静默修复、不在同版本里改提示续筛成功。后续修改要另立版本。即使本批全部通过，也不能直接沿用旧校准器、64分界或旧9轮性能。
