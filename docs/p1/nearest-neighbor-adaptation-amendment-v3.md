# 最近邻适配候选补充v3：目标比例分界与信息重合

2026-10-25，新v8验证采集前登记。用户保留单GPU本地推理方向，不用模型API。G1待审。本页继承v2目标主场景加权定义，旧v7平衡样本诊断原样保留。

v7报告的普通85%分位数36来自12交互/12后台等权校准，旧64是旧任务版本的历史阈值。它们是v7诊断项，不是当前3B下按200交互/30后台目标比例重算的NN分界。按原v2定义，把v7校准中每个类别/输入桶的4条观测分别赋予目标桶计数/4的权重，目标桶交互67/67/66、后台10/10/10，累计权重首次达到85%的最小实际输出值为12。计算仅读取冻结v7校准24条，不读取开发输出来选阈值；v7普通分位36和全短72/0仍是原口径下正确记录。

本次冻结候选为v7已选类别×公开任务种类输出中位数预测器及目标加权分界12。v8新开发资料、流量、分界和分析在新结果前登记；不根据v8结果调阈值或重新拟合。固定C指令与值域语法保留，不能把格式合法当正确业务完成。

当前预测值交互为5、6、12，后台为34、36。因此分界12下，预测短等于交互、预测长等于后台；输出预测的二分类在这类固定目标数量任务上没有提供业务类别以外的区分。不能调整分界或重写任务来制造更易被M击败的对照，也不把分出的两类当作预测信息价值证据。

标签重合不推出NN整套规则等于现有简单规则。现有简单原型带5000ms后台老化；NN请求级适配还受短准入计数、欠账和历史等待阈值影响。v8只用4个无模型状态见证核对候选先后：新后台且无债务时相同；老后台且无债务时可能不同；老后台且有债务时相同；历史阈值低于5000ms且有债务时可能不同。见证只说明所写选择规则在给定状态下能否不同，不是实际引擎NN实现、实际触发频率或收益。不得把无老化的弱优先规则当现有强简单对照。

G1候选可保留加权12，并明确标签重合；G2/G3仍须按v1/v2记录计数、债务、历史与实际启动，才能核对整套行为。输出长度不等于总处理成本，公共软工作量需同时核对输入处理阶段的作用；正式硬容量始终按输入加最大输出预留，不随预测缩小。
