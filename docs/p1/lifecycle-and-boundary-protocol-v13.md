# P1继续补强v13：异常回收与作用边界

2026-10-26，新代码及本轮新测量之前登记。承接固定量表84分，仍为P1开发验证，不代替G2/G3完整C++与KV生命周期验收，G1待用户评审；最终资料禁止生成或读取。旧v11/v12代码、原始记录与报告保持不变。

## 问题与范围

先修共享Python原型的具体异常合同：未发送、在队列中取消/超时、已发送并在模型运行、明确HTTP拒绝、释放证据缺失，必须走不同路径。原始请求终态与控制层错误分别记录，不能因回收出错把所有终态都改成failed。正常完成且输出数已知且未超上限的请求，确认释放后才能反馈；取消、失败、拒绝、超时和未完成均不反馈。

永久超过每请求2048预留的请求在客户端明确拒绝，不等到超时。硬预留仍input+max_tokens+1，总4096、最多2在途；老化5秒、在线窗口32/q0.8和同信息比较不变。

## 回收证据

- 未获得额度，或确实没有写出HTTP请求：不等待原生释放。已经获得但未发送的额度，可按not_sent归还。
- 原生CAP已记录启动：必须等该请求CAP释放，不以HTTP结束、全局空闲或预测短为替代。
- 明确HTTP400/429/503且无原生启动：仅在本脚本独占的引擎实例中，服务端已确认拒绝并查询全部slot空闲后归还；记录独占实例的假设。
- 已发送、无启动/释放、又无上述拒绝证据：达到3秒清理上限后隔离额度、阻止新放行，使批次技术验收失败。不能为了闭合把额度直接归还。

同一请求回收/反馈至多一次。取消不能打断已经开始的有界清理；清理不改请求传输终态。停止时必须写出隔离/未释放状态，并先排空请求记录再抛控制层错误。遇到写盘失败或其他技术错误，保留记录、停止批次；修复另建run_id。

## 先合成故障，再真实引擎验证

合成TCP/事件注入单列为工程测试，至少覆盖正常、排队取消、排队超时、运行取消、运行超时、明确拒绝、连接失败、SSE截断、统一截止、重复回调、丢失释放隔离及释放读取异常。期望发生的拒绝/超时不算测量失败；缺失释放负例必须确实阻止放行。

通过合成门禁才连接既有本地3B和原固定引擎：同一独占服务测试正常、排队取消/超时、运行取消/超时、明确本地容量拒绝、HTTP错误、统一截止；每个异常后再发正常请求，确认同服务恢复与CAP闭合。先做一次小批；技术失败保留，修复另开目录。不采集算法收益，不扩大正式矩阵。GPU正确性请求、预热、合成测试分别计数。采用实际分词、同模型/引擎SHA、输入上下文检查；用于测试永久超界的本地负例明确列外，不发送引擎。

原生小批固定8个场景、10条主请求，每场景后1条同服务恢复，共18条正确性请求，另2预热。复用v11已见公开提示作夹具，不称新独立资料。预算固定100代理毫秒，专用于制造确定的排队，不作性能选型；排队请求10ms到达，80ms取消或80ms期限；运行请求150ms取消/期限；统一截止50＋50ms。正常请求期限10秒、统一排空10秒；回收上限3秒。HTTP错误用非法grammar触发引擎400，目标failed且不得反馈；超容量负例目标rejected且不得发送。8次恢复须全部正常完成、无控制错误。不得把这类故意超时/取消算成算法性能成绩。

## 从已有真实状态计算完整预算边界

复用v11-r3/v12所有已记录真实决定，不新增GPU测量，也不称独立验证。对硬容量允许、非空系统且非老化例外的状态，若M成本与B3_0不同，计算能让放行分叉的完整预算区间：

`[在途成本+较小的新请求成本, 在途成本+较大的新请求成本)`。

这是固定同一状态下的精确区间，不是改变预算后整个队列的反事实性能。报告全部区间、宽度、相对锁定预算的距离，以及空系统/老化/硬约束屏蔽的数量；校验下边界、区间内点和上边界。不得选一个有利预算直接宣称在线算法有效。

若记录微基准，三策略使用相同实际状态输入，单独计长度/余量计算，排除影子、I/O、HTTP和模型执行。运行环境、有限重复、顺序与每次数据保留；只作为Python组件开销，不能外推C++或端到端代价。
