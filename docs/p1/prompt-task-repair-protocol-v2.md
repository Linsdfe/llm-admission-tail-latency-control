## 问题与本轮唯一候选

上一轮选例显示：增加输出上限后，自然结束变多，但仍有复述记录、循环、未完成两句/六点及无依据结论。依据见[上一轮白话报告](../reports/20261024/P1扩大校准与输出预算检查.md)。本轮验证单一提示v2能否改善任务遵循，不选择使M收益更大的任务、长度或输出预算。

v2保留原任务、数字与生成记录机制，把参考记录与任务分开，明确记录的用途，并将原任务置于末尾重申。聊天仍要求两句话；后台仍要求六点，每点有依据和行动；没有足够信息时应说明不足，不能编造阈值、趋势、记录或换算。系统提示保持简短，不注入标准答案。实现与提示全文在新`p1_workload_v2.py`中冻结，只有这一个候选，不在本批输出后静默改提示。

模型、量化、原始顺序原型、单进程2slot各2048、温度0、自然EOS不变。聊天最大输出64、后台384不变。v2不是强制输出长度，也不增加输出上限制造软决策空间。

## 缓存和执行设置

本轮所有40条测量及2预热均显式`cache_prompt=false`，新v1对照也重新运行；保留原始native计数并核`cached_prompt_tokens=0`、`new_prompt_tokens=input_tokens`。源码已支持逐请求开关，不改冻结客户端。若实际不符合则停止核查，不把缓存量填成0。tokenize仍为`add_special=true,parse_special=true`，原生`/completion`显式ChatML。

这是相对旧批的明确公共执行差异，不能直接用旧cache=true记录当作本次v1配对，也不与旧9轮性能混算。交替顺序与关闭前缀缓存不能证明消除全部温度、执行位置或数值差异；本轮只作串行质量和长度描述，不做时延改善因果结论。
