# QBA请求级适配卡 v1

核对日期：2026-10-24（Asia/Shanghai）。状态：P1草案，待G1审查；规则未实现，参数未冻结，未产生本方法的性能结果。

这张卡拟引入一个已有的强对照：多数时候先接预计较短的请求，累计接够若干条短请求后，为等得久的长请求保留一次优先机会。它用于检验已有规则能解决多少问题，原课题的M/B3增量比较继续保留。

## 2. 原规则保留什么

| 方面 | 原方法事实及定位 |
|---|---|
| 状态 | 预测短/长队列、历史等待分位阈值、短准入计数、最多一笔提拔欠账。§III-A4、A6 |
| 触发 | 长请求等待超过阈值才具备老化资格；短计数达到k才产生欠账。§III-A4、A6 |
| 动作 | 有欠账时优先提拔最老的合格长请求；未实际准入不清债。§III-A6 |
| 计数边界 | 短请求全部完成prefill后计一次，未完成的prefill续块不重复计数。§III-A6及作者代码 |
| 有限承诺 | 每个配额周期至多一次债务提拔；不是端到端时延上限。容量约束仍生效。§II-A3、III-A6 |

原实验采用服务仿真，主实验预测标签与实际长度标签一致，另测误分类；本文拟采用真实点预测器，因此不照搬其数值结论。[原文§IV-A2—4](https://arxiv.org/html/2610.17795v1#S4.SS1)

## 3. 本项目拟怎样适配

以下均为本项目的设计建议。运行环境沿用P1单实例、非抢占设置；进入执行的请求继续运行，NN-QBA只调整尚未准入请求的次序。执行器内部批处理和prefill设置保持公共配置。

**预测长短与业务类别分别保存。** I/B表示聊天/后台；S/L表示预测短/长。不能直接把I当S、B当L。

使用与M/B3相同、只由校准数据建立的冻结点预测器，得到输出长度预测`D_hat`。拟以校准集实际执行输出长度的85%分位数`tau`为固定分界：`D_hat <= tau`为S，否则为L。并列值归S；预测先裁剪到本请求输出上限。最终真实长度只用于事后分析，不能回填准入决策。

预测器即使使用I/B特征，S/L也必须由预测值与tau计算。逐轮报告I/B与S/L的2×2请求数、实际长度和预测误差，检查是否退化成业务标签优先。

| 状态 | 请求级草案定义 |
|---|---|
| `c` | 上次债务提拔后实际准入的S数，初值0，最多为k |
| `debt` | 是否欠一次合格L提拔，初值false，最多一笔，不累加 |
| `H` | 本轮已经实际准入请求的排队等待历史，只含决策前可见值 |
| `theta` | H足够时取其gamma分位数；不足时用公共老化阈值T作回退 |
| `aged` | 尚在队列且预测为L、当前等待严格大于theta的请求 |

H拟保留最近128条；不足32条时回退T。T沿用公共开发选择，不单独给NN调优。H只在实际准入后追加，从计划到达到准入计算等待；两条模型预热不加入H。每轮重置c、debt、H，避免上一轮结果泄漏。

## 4. 每次有准入机会时怎样操作

1. 清除已取消、已到总期限或已进入其他终态的请求。请求没有实际准入，c、debt、H不变。
2. 从当前H计算theta并标记aged；本次准入产生的等待样本只能用于后续决策。
3. 若debt存在且aged非空，候选次序为“最老aged L、S按到达、其他L按到达”；否则为“S按到达、L按到达”。相同到达时间按固定请求ID排序。
4. 逐个检查公共硬守卫。最前候选当前不满足可恢复容量条件时，本草案建议保留次序、等待下一次容量释放，不跨过它另选请求；这是与原作者代码停止扫描方向一致的保守选择。永久超容量请求按公共规则拒绝。
5. 在同一串行提交过程内完成容量预留、执行交接和实际启动确认，记录选中原因及债务版本。被选中、发HTTP、预留尝试或客户端结束，都不能替代服务端实际准入。
6. S实际准入后执行`c=min(k,c+1)`；达到k则置debt=true。欠账期间继续接S不增加欠账，也不把c清零。
7. 只有带本次债务提拔标记、并实际准入的aged L才能执行`debt=false,c=0`。没有提拔标记、仅因无S而自然准入的L不清债；没有合格L时继续保留债务。
8. 预留失败、交接失败或启动前取消时撤销本次尝试，不加计数、不清债、不追加H。启动后再取消不撤销已经发生的准入，回收仍走公共路径。

两slot并发时也只允许一个提拔提交在途，避免同一笔债务被消费两次。启动确认及回滚的具体可观测边界在G2/G3确定，P0的CAP日志不能代替尚未实现的公共硬账本。

这里将原方法的“短请求prefill全部完成”改为“请求首次实际占用slot并启动”的一次性计数。它是明确的请求级适配差异；若G2能取得可靠prefill完成事件，可另立版本保留原计数边界，不能混用两版结果。

## 5. 与现有对照怎样区分

| 对照 | 与NN-QBA的区别 |
|---|---|
| B2-Q固定服务配额 | 配额直接规定I/B服务机会；本卡用预测S/L、历史分位老化和最多一笔欠账。B2-Q具体定义仍待G1，不能只换名字 |
| S_cap1 | 限制同时运行的B最多一条；本卡不额外加入此上限，公共硬容量允许时仍可同时运行两条B |
| B4预测长度排序 | 直接按公共预测值排序；本卡先做二分类，再给合格L受限提拔 |
| M/B3 | 两者之间仅比较在线/固定软余量；NN另改候选顺序和老化逻辑，因此NN比较估计的是整套规则差异 |

NN共享硬守卫、预测器、请求、缓存、执行器、输出上限、时钟与终态定义。拟不额外叠加M的在线余量或另一套单独软预算；否则无法判断QBA规则本身的作用。业务类别和预测误差可用于同口径分组分析，不能向NN提供未来长度。

## 6. 参数、预算及实现检查

候选四组`(k,gamma)`拟定为`(2,0.80)、(5,0.80)、(8,0.80)、(5,0.95)`，包含原文默认点；tau、历史长度和回退规则不再交叉搜索。它们都是待G1选择的建议值，不是已找到的最佳参数。

建议NN、M和B3各最多评估四个候选，每候选使用相同三组开发数据；公共配置搜索另单列并共享。都按P1相同可行性、排序和并列规则锁定，失败与不利结果计入已用预算。若G1改变候选数，应同时调整三者预算并留版本。

实现前需要可复现地检查：未启动不计数；k次短准入才生债；欠账不累加；过期或容量阻塞不清债；实际提拔恰清一次；无短队列仍可服务长请求；双slot不重复提拔；各轮状态重置。

日志拟逐决策保存预测值/类别、theta和历史数、c/debt前后值、候选顺序、硬守卫结果、实际启动/失败及提拔原因。实测报告聊天和后台全部终态、等待、整体速率，以及预测S/L的等待分布和实际提拔次数。

## 7. 证据边界和G1待审项

在上述提交规则成立、初始无债务时，债务提拔数不超过`floor(实际S准入数/k)`；这只是本草案可检查的计数不变量。普通L准入不受此数限制，欠账也不保证立刻执行。过载、容量阻塞和持续长请求到达下，没有有限等待或不饿死的无条件保证。

本卡未复现作者的token级仿真、prefill续块优先、批服务时间模型、队列近似、合成负载、Azure轨迹或预测误分类实验；原文标签设定也不等于本项目的真实点预测。公开仿真代码可参考，不等于真实引擎已复现原系统，更不能把配额老化写成本项目原创方法。

G1需决定：是否接受请求级计数差异；硬阻塞是否停止扫描；预测分界、历史回退和四组候选是否合理；同预算是否落实；原代码版本及引用是否齐全。通过后再排实现与验收，不在此处代填G1通过。
