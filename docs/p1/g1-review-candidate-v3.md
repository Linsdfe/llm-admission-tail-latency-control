# G1候选v3：作用空间与负面交付补齐

2026-10-26。以[候选v2](g1-review-candidate-v2.md)为基础，仅下列明确变更优先；v2、原冻结清单和旧数据保留。G0已通过，G1仍待用户评审，助手不代填通过。

## 两个缺口的核对结果

1. **M/B3不是逻辑上无法区分，但现有资料上的校正需求很小。** [回顾性机制诊断](../experiments/20261026-p1-margin-mechanism-audit-v1/summary.json)用48份已见开发资料、外生单条完成反馈构造2×230次输入，4个M候选共1840次诊断决定。M余量只出现0或1；相对B3=0，544次多留1token、1296次有效预算相同，且多留的均在冷启动回退阶段。全部48份真实已见输出已在B3=0＋公共语法下限以内，非核对任务没有正残差。构造的同一剩余空间状态能使两者一放一等，但不代表真实队列到过该状态，更不代表M改善延迟或吞吐。原生触发仍在G2/G3核验。
2. **研究不再以M必须获胜为交付条件。** [负面结果交付计划](negative-result-delivery-plan-v1.md)明确系统、正确性、对照、方法成本、区间判读、论文各章及不触发时处理。原题的同信息M/B3比较保留；不靠改负载、加噪声或移除公开有效信息制造收益。

## 修订公共预算，避免只看交互占比

[预算口径诊断](../experiments/20261026-p1-budget-reference-audit-v1/summary.json)中，v2目标权重P75参考成本约292.744代理毫秒；三个候选预算下，24/24份后台来源任务自身成本都超过预算。普通非空状态下，即使当前剩余工作为0也不满足软准入；空系统/老化绕过仍可服务，所以这不是实测饥饿证据。

v3改为分别计算校准交互、后台参考成本的P75，再取两者较大值，三个倍率仍为0.5/0.75/1，组合和搜索预算不增加。这样改是保证参考值考虑两类请求的量级，与M能否获胜无关。现有校准点估计成本的示例参考约1048.606代理毫秒；对应示例最大预算下，开发24后台中14份自身成本不再单独超过预算，10份仍需等待/绕过条件。这个示例不是正式冻结数值或性能改善。

正式校准参考成本使用同一规则下的公共有效长度（B3余量0，核对取公开分支下限），输入系数median(prompt_ms/prompt_n)、输出系数median(predicted_ms/predicted_n)。输入/生成耗时和token必须已知。按类type7 P75取max。**示例诊断的校准成本未枚举校准编号的核对分支，故正式参考必须在G3按完整公共规则重算，不能照抄1048.606。** 初始点、公共下限、容量与真实工作状态仍需G2/G3验收。

共同配置选择仍先检查服务/代价和全部终态，再按原排序，在3预算×3老化、相同3开发块上选定，给所有方法固定。若所有候选主要依靠绕过、后台缺少普通服务机会，记录并暂停公共配置冻结，按开发前的可服务性标准审查范围；不能因为M没有赢就改预算或选择规则。

## 消除实现歧义，保留后续门槛

残差历史明确按类别×任务种类分6桶，校准按桶暖启动；最少32包含暖启动样本，每桶滑窗32/128，分位type7向上取整，残差非负，不足回退校准交叉验证最大正残差。只读严格早于当前决策的已完成反馈，预热和未知输出不进桶，各运行重置。G2还须定义同时完成事件顺序、剩余工作推进和一次性启动/回收合同。

G3必须记录真实决策空间：有效余量不同次数、公共下限吸收次数、候选等待/放行不同次数、实际启动差异、反馈可见时刻及绕过次数。离线见证、外生反馈和单条处理时长不能替代这些原生证据。G3检查能触发但不要求M胜；不触发时按负面交付规则处理，不自动删除不利方法。

其余模型、场景、全历史查重、最终未见、价值线、20块统计和320轮正式上界、96轮开发上界及资源预算沿v2。新增核对为零GPU测量，只用已见开发证据。导师/学院认可与异地原始数据保存仍分别留意见，不冒充已落实。
