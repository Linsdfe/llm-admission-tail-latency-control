# 可核对资料任务v3：采前确定性核对规则

登记日期：2026-10-25，Asia/Shanghai。在本轮模型输出之前固定；适用于单一v3、24条开发pilot，不覆盖v1/v2量规或旧结果。

## 核什么

三类任务都只使用提示中明示的资料和目标ID，不要求开放分析或固定两句话：

| 任务 | 独立标准答案 | 必须核对 |
|---|---|---|
| 提取extract | 从`source_records`按`target_ids`顺序取出原始字符串值 | ID、值、目标覆盖、顺序 |
| 核对check | 同ID的`left_records`与`right_records`值相同写“一致”，否则写“不一致” | ID、逐项比较结果、目标覆盖、顺序 |
| 整理organize | 从`source_records`按指定`target_ids`顺序重新列出原始值 | ID、值、重排顺序、目标覆盖 |

每条输出一行`ID|值`或`ID|结论`，使用ASCII竖线。评估器从资料事实独立推导答案，不导入生成器，不以生成器给出的expected文本作为判断依据；另核两者一致。所有目标必须在所需来源中存在且唯一；来源重复、目标缺失、空字段或非法值属于题目/证据不合法，评估应停止核查，不能把虚构补值当答案或将题目错误记成模型答错。

资料事实和目标顺序应确实在prompt中出现并与独立结构化参考相符。`expected_lines`、`expected_answer`及完整核对参考只放本地evaluation计划，不能注入prompt或HTTP请求。推理侧计划与原生客户端采用白名单字段；实际隔离由冻结客户端源码、HTTP捕获单元测试和原生输入记录交叉核对。按源码重建的payload不能冒称真实网络抓包。

## 主判允许的空白标准化

只做以下不会改事实的处理：将CRLF或CR统一成LF；忽略纯空白行；每个非空行必须恰有一个ASCII `|`，拆成两个字段后去掉各字段首尾空白。保留原始全文及字节SHA。

例如`R1|42`、` R1 | 42 `以及前后带空白行的同一条记录，标准化后等价。主判逐行比较标准化的ID和值，不再因这些良性空白判业务失败。原始UTF-8字节与紧凑expected文本完全相同另外报告，不作为主进入条件。

不会做：更改大小写、数字写法、ID、单位或“一致/不一致”标签；交换行序；删除非空表头、解释、代码围栏；将全角竖线改为ASCII；删除重复或额外记录；补漏行或修正字段。`42`与`042`、`一致`与`相同`都不自动等同。

## 分项输出与进入条件

每条保存独立标准答案、原始回答、标准化字段、逐项差异，以及：结构是否可解析、字段值是否一致、顺序是否一致、缺失ID/多余ID/重复ID、非空额外文本或非法行。分项可能重叠，不相加成单一质量分数。EOS、未触顶、低重复或原生技术检查通过都不能代替答案核对。

预先要求24/24条在允许空白标准化后事实、覆盖和顺序均完全正确，且没有非空额外文本，才允许另登记新的长度与小规模开发负载检查。一个失败、题目不合法或无法确认都不按通过处理。这个门仅用于继续开发，不批准G1，不证明总体业务正确率或复杂算法收益。

评估代码需在真实输出前通过反例单元检查：正确与良性空白等价；错值、错ID、错标签、错序、漏/多/重复行、额外说明、表头、围栏、全角分隔、单位/大小写/数字写法变化均不能被“清洗”为成功；目标未提供或来源重复必须拒绝构造标准答案。
