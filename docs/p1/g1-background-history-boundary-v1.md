# G1必须知情的后台样本边界

这是候选v3现有6桶/最少32条规则的推论，不改变任何参数或数据。

每轮30条后台按既定输入桶与资料池轮换后，提取/核对/整理实际出现12/10/8次，并非三类各10次，每桶最多12条反馈。v9校准每桶8条，合计最多20条；拟定正式96条校准时，每桶16条，合计最多28条，仍少于32。因此该候选中后台整轮使用校准固定回退，不会进入自己的在线分位数更新。现有离线诊断的240次后台决定全部回退，与此一致，见[样本边界核对](../experiments/20261026-p1-margin-mechanism-audit-v1/sampling-boundary.json)。

本候选可研究交互桶的在线变化与全系统等待/后台代价，不能声称两类请求都得到在线校准。核对语法公共下限还会吸收小余量，使M的增量空间更小。G3日志应逐桶记录这一事实，不用全局“在线更新次数”掩盖后台未更新。

G1若接受此范围，可以按候选进入G2并允许负面结论；若课题要求两类均产生在线更新，应在G1明确修改分桶或采样规则、另登记版本并重新核对，不能在看完M性能后临时降低样本门槛。本次不为触发在线机制而改阈值、拼接最终数据或增加后台负载。
