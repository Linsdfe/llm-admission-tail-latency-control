# P1输出约束配对验证协议v4

## 问题与唯一干预

v3的24题只有9题完整正确，既有漏编号、多余记录、错标签，也有真实抄错数和比较错误。本轮检验：固定同一模型、输入任务和预算，增加解码时输出语法约束，能否减少格式失败，以及约束后还剩多少事实错误。

引擎固定源码`tools/server/server-schema.cpp`的grammar字段支持GBNF，`server-task.cpp`保存生成设置；实际是否执行由逐请求原生`generation_settings.grammar`回显、合法输出及引擎日志共同核查。本轮不改引擎二进制或服务器全局语法。

无约束U只发送原8个字段；有约束G在同一payload上增加grammar。prompt、资料、目标列表、模型、引擎、温度0、自然EOS、缓存关闭、最大输出64/384不变。语法从公开任务指令获得目标ID、数量和顺序，固定这些结构；数值允许10—99全部90种，核对允许“一致/不一致”两种。语法同时约束结构和字段域，不能把格式通过称为模型自主遵循能力提升。

构造语法只能接收prompt和类别，不能读取expected或结构化资料值，也不依据模型回答改语法。改变资料值和正确答案而保留目标指令时，语法必须完全不变。正确答案仍仅保存在离线评价计划；固定ID和顺序属于公开任务要求，不属于注入正确数值。源资料本来包含待提取事实，是业务输入。

## 样本、配对与计数

只用24道全新开发题，seed24001。v4生成器保留v3的三种任务、资料schema、目标数量、输入桶及prompt模板，仅登记新开发种子和独立ID。每种任务8题，每类4短请求、4后台；六个类别×输入档各4题，各任务种类跨全部输入桶。

每题U/G各跑一次，紧邻配对。`kind_instance`偶数先U后G、奇数先G后U，共12对UG、12对GU；每类别×任务及每类别×输入桶均2对正序、2对反序。计划顺序在输出前保存，不根据题目对错或长度调整。两次prompt和实际输入token IDs必须完全相同，只更换请求ID与grammar字段。

48条测量＋2条独立预热，共50次completion，预期100条CAP启动/释放事件。24题是配对描述单位，共享同一次服务，不将48条视为独立性能重复。历史v3的9/24只作背景，不与新G跨时间直接相减。校准与最终数据均禁止生成、读取、拟合；不抽取旧9道成功题。

短请求提取/核对查1项、整理查2项；后台各6项。每臂24题、**88个预定目标字段**。输入桶沿用短32—79/80—143/144—256，后台128—319/320—639/640—1024；只增同schema资料行以达到实际分词长度，不加无关填充。自然回答变短或长短重叠如实记录，不加目标或强制输出制造调度空间。

## 判分与继续条件

按[评价量规v4](output-constraints-evaluation-rubric-v4.md)独立从源事实重算正确答案，验证完整真实prompt与离线资料/目标一致；沿用v3的良性空白标准化。主判是每臂完整正确/24、配对“都对/都错/U错G对/U对G错”。另报合法结构、目标覆盖、顺序、88字段正确数及逐字段差异。漏项、重复、非法字段不从分母消失。

G语法执行和格式正确不自动代表事实正确；比较标签或值有错即业务失败。全部48次结束后统一判分，保留原文和所有失败，不中途按质量补样。补读全部24对原题/回答，记录为助手知晓版本核读，不冒充学生或导师盲评。

G24/24完整正确且技术完整性全部通过，仅允许另登记新校准/小负载开发，不批准G1、不证明总体可靠率或算法收益。未达就保留本批，列出剩余问题；不在同版本修改语法或提示续筛成功。无论结果如何，旧估计器、分界64和旧九轮性能均不直接套用。
