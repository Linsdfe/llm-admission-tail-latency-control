# v11-r3增长日志读取修复

r2探针再次因缺少释放确认停止。对应CAP RELEASE实际存在于服务日志，但控制器未捕获，不能把它解释为引擎未释放或算法代价。保留r2所有记录。可能原因是增长文件的整段读取在ENODATA异常时底层位置已推进，忽略错误不足以防丢数据；这是根据漏读与异常作出的诊断，不是对WSL文件系统内部行为的完整证明。

r3使用无缓冲、每次最多65536字节、明确字节偏移的读取；只有成功返回的字节才推进已确认偏移，暂时无数据不推进，下次重新定位，其他错误仍失败。继续保留3秒释放确认上限，不因漏读扩大或绕过安全线。新增偏移不跳跃回归，WSL实际共享文件1000组启动/释放追加压力测试，以及合成TCP门禁；它们不是GPU效果证据。

使用新的运行目录和来源快照，复用父批次144条有效校准，仍只重跑B3_0预算探针和原登记6轮；r2补充判读、点模型、数据、反馈、预算候选与比较次序不变。所有旧失败保留，复用校准不能重复计成新数据。G1未自动通过，最终未生成或访问。
