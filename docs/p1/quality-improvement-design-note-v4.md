# P1质量补强后的设计边界与待评审修改

本文件记录v11/v12开发验证带来的修改建议，不覆盖旧G1候选，不代表G1已通过。正式数据与参数仍须评审后锁定。

## 统一采前门禁已进入实际入口

新资料在首次模型测量前经过全历史/批内提示查重、真实分词输入桶、输入＋用户最大输出＋1的上下文检查、允许split/seed及暖启动样本计数。冲突只用预定事实nonce重采样，不看输出。已将旧v10的2份重复、实际80token却要求≤79的提示、旧48校准每桶不足32的问题作为回归负例；它们确实被同一门禁拒绝。

技术复跑是明确例外：只复用已登记的同一资料与有效校准，按父运行和逐文件SHA追踪，不能当成新独立资料；原失败保留。正常新资料仍不能绕过全历史检查。

## 样本量与真实反馈

保留6桶和最少32条，补采144条独立校准资料，与已有48条合成每桶32的暖启动。完成反馈只有在原生CAP释放被观察到后才能进入历史，外部额度也到此时才归还；预测绝不减小按最大输出的预留。

如果正式研究仍采用6桶、每轮200/30和32条门槛，原96条正式校准每桶16仍不足以让后台可靠进入更新。建议正式校准改为8个新seed×24＝192，每桶32，拟用30101..30108；旧30101..30104范围仅扩展，均尚未执行。点模型交叉验证相应按8个seed留一，实施与独立核对留G2/G3。新开发补采311xx不冒充正式新校准，最终391xx/392xx仍禁止访问。

## 硬容量与软估计的角色分开

v11的公共语法最大长度作为软估计下限，是一个保守策略，不是硬安全条件。v12探索把它当上限裁剪：M/B3都保留同样信息，硬容量仍按用户最大输出保护。两角色的旧记录都保留，不因M是否获胜删掉其中一个。

下一版正式方案需明确选择研究的软成本角色，并保留保守公共语法策略作强对照；不能把角色修改悄悄混进M/B3的余量差异，也不能用跨时段开发结果直接宣称角色的因果性能收益。原320轮只是未批准方案的上界，新增强对照后需重新列矩阵和预算，不能边跑最终边决定。

## 公共配置先过可服务性检查

“normal-only至少一半”把合法空系统启动也当成问题，不合适。新补充标准在首个探针结果前登记，分别要求全部计划完成、后台normal＋empty至少15/30、自身公共B3_0成本落在预算内至少15/30，并单列aged启动。50%只是诊断工程线，非业务SLO。旧normal-only口径与所有失败保留，不能重标为按原标准成功。

本次公共成本与预算只从校准及B3_0探针确定，不用M结果选择。正式方案应在更多开发资料上确认这一规则的适用性，保留“不通过则停止配置冻结”的分支。

## 研究主张仍有边界

这些是可核对合成任务，模型答案质量与系统完成/性能分开。当前小原型不等于正式C++控制器、完整KV生命周期或生产开销测量。固定语法可能使在线校准没有增益；这本身不该靠制造误差修补，但也不足以解释一般LLM请求的复杂度取舍。

后续若要支持更一般的研究结论，应另登记有自然输出工作量差异、事实和证据仍可核对的场景，保持同信息强对照和未见最终测试，而非根据M输赢筛数据。若保持当前范围，就把结论收窄到受限格式负载。固定五项工作质量量表继续使用，不把文件数量、运行数量或M是否获胜当评分依据。
