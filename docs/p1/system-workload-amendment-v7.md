# P1 合成系统负载与质量记录补充 v7

2026-10-25在新采集前登记。用户决定保留原单GPU推理准入与尾延迟方向，继续本地部署，不用远程模型API。本轮执行协议见[负载验证协议](system-workload-pilot-protocol-v7.md)。G0沿用用户通过决定，G1仍待评审。

v6固定3B模型在24道已见开发题上20/24完整正确，未满足原24/24入口条件；这一结论、原量规和原始输出全部保留。本补充不追改v6的通过状态，也不把20/24改称业务合格。

此前把模型语义全对作为系统调度摸底的共同硬门槛，混合了模型能力与系统控制两个问题。现按研究目标另行登记：本轮资料题是透明的合成系统负载，用于观察真实生成工作量、排队和简单规则取舍；不是必须使用LLM的实际业务示范。调度性能与事实正确性分别报告。固定字段可由普通程序精确处理，不能据此声称LLM业务创新。

技术有效性要求来源、计时、实际token、资源回收与终态完整可核对。答案错误不触发早停、不删请求，全部计划请求保留在终态和质量分母中；已完成请求的延迟标注其范围，并公布首内容覆盖、未完成和失败。技术完成不等于答案正确；另报完整正确题数、正确字段、正确完成任务速率和错误原文。若性能改善伴随质量变化，不能仅据token速率宣称正确业务交付改善。

当前固定3B、原明确指令、公开ID/顺序/值域语法、自然EOS和输出预算。使用新内容、新种子；不按成功答案挑题、不复制v6正确题、不拉长无关答案制造控制空间。本轮校准/开发按内容及种子隔离，共用公开指令模板，明确不声称未见模板泛化；正式三份数据及最终模板家族仍须G1另行冻结，最终测试不生成、不读取。

本轮只完成新模型单条剖面、有限预测候选重校准和三个已有原型规则的有限突发对照。正式硬KV账本、B3/M和NN-QBA都没有因此实现或验收。P1报告方案和机时；G2/G3再核硬容量、回收、决策机会和最小实现，后续正式对照才回答复杂方法是否值得。
