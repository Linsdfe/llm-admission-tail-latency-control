# 最近邻适配候选修订 v2：长短分界与业务类别重合

记录日期：2026-10-24，Asia/Shanghai。P1开发期修订，G1待审。原[QBA请求级适配卡v1](nearest-neighbor-adaptation-draft-v1.md)及采后问题记录保留；本页只修订分类候选和后续核对要求，不表示规则已经实现或G1已经冻结。

## 本轮得到了什么结果

依据[扩大校准执行协议](calibration-refinement-protocol-v1.md)，本轮用120条新校准选择预测器、计算阈值，再用120条新开发请求验证。两个中止批、旧24条校准和旧2010条负载测量均未并入训练。完整数字见[本轮分析](../experiments/20261024-1926-p1-calibration-refinement-v1-final/README.md)和同目录`model-artifact.json`。

五折留一校准种子的主场景加权绝对误差，中位数为17.833261 token，均值为20.291902 token，按采前规则选择中位数。新开发验证只检验这个选择，不用于重新选模型。候选公共预测器仍须与M/B3共享，不能给最近邻另配较弱预测器。

主分类候选采用目标主场景比例加权的校准实际输出85%分位，结果为64 token。目标权重是200条聊天、30条后台及各输入桶比例，并非把本轮平衡采样的120条等权汇总。定义为累计权重首次达到85%的最小观测输出值，预测不超过64归短，超过64归长。原平衡样本的普通85%分位为384，仅作敏感性参照，仍导致全部预测归短。

| 新开发验证业务类别 | 预测短 | 预测长 |
|---|---:|---:|
| 聊天 | 60 | 0 |
| 后台 | 0 | 60 |

主候选不再全部归短，但预测长短完全等于业务类别。按受64/384上限约束的实际执行长度分类，本轮误判短、误判长均为0。这不是无上限自然长度的分类结果，也不证明回答已经完成任务。

聊天占目标主场景的200/230，超过85%，且聊天输出不超过64，所以这种加权85%分界必不超过64。本轮的类别重合与预算和业务比例有关，不能把分类结果当成“预测分类额外提供了信息”的证据。

## 候选怎样保留

将“公共中位数预测器＋目标主场景加权阈值64”登记为待G1审查的分类候选。64由本轮校准和采前定义算出，不是看新验证结果后挑的阈值。不能再根据这120条验证数据调整阈值、筛提示或更换估计器，来制造一个更容易被M击败的最近邻对照。若以后修改任务、预算、模板或阈值定义，须另立版本并重新验证。

分类与业务标签重合，只说明本轮的分类输入没有表现出额外区分。QBA候选还包含短请求计数、至多一笔提拔欠账和历史等待分位老化；这些规则仍可能改变请求的准入顺序。因此不能直接宣布整套QBA已经等于简单业务优先或固定服务配额，也不能仅靠改名字就把它当成新增的独立强对照。

## G2/G3需要怎样核对

在相同请求、容量、取消、期限和实际启动边界下，逐决策保存预测值、64分界、预测长短与业务类别，并记录候选次序、`c/debt/H`变化、老化阈值、提拔原因和实际准入结果。分别与简单业务优先、固定服务配额核对真实选择顺序和实际提拔，不能只比较类别表或最终性能均值。

若指定场景和参数下，实际顺序、提拔及终态处理均等价，就登记这些配置之间的别名映射，明确等价的条件和证据；调整矩阵时避免将同一行为当成多个独立方法或重复贡献。有限轨迹上的一致不能推出所有负载都等价。若观察到差异，应定位到欠账或历史老化的具体分支，再评价整套规则的收益与代价。

本页没有实现QBA、M/B3或公共硬账本，也没有正式性能结果。G1仍须审查分类候选与对照范围，G2/G3再验证实际介入和行为差异。
