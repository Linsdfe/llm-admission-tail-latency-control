# v12开发对照：公开最大长度在软估计中的角色

2026-10-26，v11真实试跑之后、新v12输出之前登记。v11已观察到M/B3_0的同状态判断相同；本轮为解释和修正过度保守设计的探索，不是独立未见验证。旧数据、失败和v11结论完整保留，最终未生成/访问。

v11长度=max(point+margin,grammar_max)把公开最坏长度用作软预算下限。它是可选择的保守策略，不是硬安全要求，可能直接屏蔽校准信号。v12保留同样公开信息，改为soft_length=min(max_tokens,point+margin,grammar_max)，无公开grammar_max时仅裁到max_tokens。两方法同样使用最大值作软估计上限，不删除有效信息，也不拿真实答案预测。硬预留仍input+用户最大输出+1、每请求≤2048、最多2在途及总≤4096，绝不因预测较短减少。

只复用已登记v11校准和两份开发资料，192条校准暖启动（旧48＋新144）、点模型、成本系数、1.0Q预算、老化5秒、先后顺序和原生释放确认均不变；不重选预算、不重拟合、不再新增种子。预算本身仍是v11锁定值，以便诊断软信息使用方式；两阶段先后运行有时间漂移，不能把跨阶段性能差异完全归因于该角色修改。
